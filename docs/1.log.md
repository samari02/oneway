### #34 Empathetic AI coach with context & memory

**Date:** 2026-01-10

- **Prompt empathique réécrit** :
  - Personnalité chaleureuse, patiente, genuinement curieuse
  - Valide les émotions avant de conseiller
  - Pose des questions profondes sur le "pourquoi"
  - Utilise le prénom de l'utilisateur
  - Répond dans la langue de l'utilisateur

- **Approche structurée** :
  - D'abord comprendre la motivation profonde
  - Identifier les obstacles actuels
  - Visualiser le succès
  - Seulement après → suggérer des actions

- **Contexte utilisateur passé à l'AI** :
  - `displayName` — prénom pour personnalisation
  - `currentGoal` — objectif actuel
  - `habits` — liste des habitudes existantes
  - `wakeTime` / `sleepTime` — horaires de vie
  - `previousConversations` — résumé des échanges passés

- **Mémoire persistante** (`009_ai_conversations.sql`) :
  - Nouvelle table `ai_conversations` dans Supabase
  - Stocke messages + contexte par utilisateur
  - Fonctions `saveConversation`, `loadConversation`, `clearConversation`
  - `getPreviousConversationsSummary` pour inclure l'historique
  - RLS pour sécurité des données

- **Intégration modal** :
  - `NorthStarEditModal` reçoit `userSettings` en props

### #49 Extension Bypass Fix

**Date:** 2026-01-11

**Issue**: Bypass button was not working — clicking "Continue" would redirect to the original URL but immediately trigger a new blocking check, creating an infinite loop.

**Root cause**: The blocking logic had no memory of bypass decisions. Every navigation was checked against the rules, even after a user explicitly chose to bypass.

**Solution**: Implemented a **tab-specific allowlist** system:
- `allowedTabs: Map<tabId, { domain, expiresAt }>`
- When user bypasses, add tab+domain to allowlist with 5-minute expiration
- `shouldBlock()` checks allowlist BEFORE checking rules
- Automatic cleanup of expired entries every 5 minutes

**Changes**:
- Modified `service-worker.ts`:
  - Added `allowedTabs` map
  - Updated `shouldBlock()` to check allowlist first
  - Modified `handleBypass()` to add to allowlist
  - Added `cleanupAllowedTabs()` periodic task
- Modified `block-screen.ts`:
  - Send `tabId` with bypass message
  - Navigate to original URL after successful bypass

**Result**: Bypass now works correctly — user can access blocked site for 5 minutes in that specific tab.
